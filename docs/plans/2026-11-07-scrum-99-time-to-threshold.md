# SCRUM-99: detection-relative time to thresholds

Implement three fixed-type v1 definitions through the existing outcome framework: TIME_TO_THRESHOLD (categorical first side), TIME_TO_THRESHOLD_BARS and TIME_TO_THRESHOLD_SECONDS (numeric first-hit offsets for an explicitly selected side). No schema migration or detector changes. The typed single-value observation contract stays intact; configurations associate the category and side offsets through their immutable source event, threshold parameters and horizon.

Common parameters pin horizon, basis (EVENT_DIRECTION or explicit UP_DOWN), each side's nonnegative magnitude and units (POINTS or ATR), and captured ATR instance (default atr). Defaults are horizon 5, event direction, and one point on each side. Zero magnitude explicitly means a touch of the reference price. EVENT_DIRECTION uses only the known captured continuation/reversal direction contract; unavailable direction returns NOT_APPLICABLE. UP_DOWN names instrument-price directions explicitly and works for directionless events without inventing an event direction. Side offsets use POSITIVE/NEGATIVE; with UP_DOWN these mean UP/DOWN respectively. Mixed point/ATR thresholds are supported. Only a ready positive finite ATR from the selected detection-time component can construct an ATR level. No later state or alternate instance supplies a fallback. Threshold products and price differences preserve exact Decimal arithmetic independently of ambient precision.

Reference is the source analytical detection close. Read only completed canonical M1 candles in the full t+1..t+N bounded same-trading-day window supplied by SCRUM-120, starting at actual source-close availability. Inclusive high/low touches count. Record each side's first future candle independently. Return POSITIVE_FIRST/NEGATIVE_FIRST, or UP_FIRST/DOWN_FIRST for explicit UP_DOWN; a complete untouched window returns AVAILABLE/NOT_REACHED. If both sides first touch on the same candle, return AMBIGUOUS with reason SAME_BAR_AMBIGUOUS, without guessing intrabar order. Individual hit offsets remain AVAILABLE because their candle/time is known even when order is ambiguous. Later dual touches do not erase an already established first side.

Bar offsets are one-based counts of required future open-session M1 candles. Seconds are elapsed wall-clock seconds from reference availability to the hit candle's close availability; this records when a hit became observable, not a fabricated intrabar timestamp. Reference time plus seconds reconstructs its UTC close time. Scheduled closures can make seconds differ from bars times 60. A numeric side not reached returns NOT_APPLICABLE with NOT_REACHED reason and no value; the categorical result preserves AVAILABLE/NOT_REACHED. Any incomplete/gapped/day-crossing required window remains INSUFFICIENT_DATA even if an early hit was seen. Immutable definition/configuration, captured source context and existing dual-hash/dataset/calendar/build lineage make every threshold basis and offset reproducible.

Register all definitions/algorithms in the production catalog and reuse bounded owned downstream execution, cancellation/failure preservation, completion gates and idempotence. Tests cover positive/negative first, one side/neither, first-versus-later dual touch, same-bar ambiguity, exact boundary/final candle, captured direction/reversal, directionless explicit axes, ATR/mixed units and invalid/missing ATR, later-state independence, low ambient precision, elapsed time across closures, full-window insufficiency, M5 source availability, resolved configuration identity, SQL roundtrip and real queued SQLite/PostgreSQL execution. Runs/results UI and structural outcomes remain separate tickets.
