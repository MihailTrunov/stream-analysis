# SCRUM-98: captured-basis price excursions

Implement eight fixed-unit numeric v1 definitions: MFE, MAE, UP_EXCURSION and DOWN_EXCURSION in points, plus each `_ATR` counterpart in ATR multiples. Explicit canonical-M1 horizons use the existing 5/15/30/60 suggestions. Every window is FROM_DETECTION_TIME, t+1..t+N inclusive, excludes detection-bar extrema, requires full same-trading-day coverage, and is evaluated only downstream of persisted immutable detector events and X.

UP_EXCURSION = max future high minus detection close; DOWN_EXCURSION = detection close minus min future low. MFE uses UP_EXCURSION for bullish and DOWN_EXCURSION for bearish events. MAE is min future low minus reference for bullish, and reference minus max future high for bearish. These are the signed ticket formulas, with no flooring at zero. Directionless events retain raw up/down values; MFE/MAE are NOT_APPLICABLE. Share the frozen v1 continuation/reversal direction contract with forward returns; no later occurrence or component can change the sign.

ATR definitions explicitly pin `atr_instance_id` (default `atr`) in configuration. Read that component only from the source DetectionTimeContextSnapshot; require a ready, finite, positive captured ATR and component family `atr`. Divide with fixed Decimal precision 28/HALF_EVEN. Missing, unavailable, zero, negative or invalid captured ATR makes normalized observations NOT_APPLICABLE while point observations remain independently valid. Do not fall back to another ATR instance or later frame. Raw subtraction remains exact independently of ambient Decimal precision.

Reuse the registered outcome worker and observation lineage/idempotency model, keeping all units and normalization semantics in versioned definition fingerprints. No schema migration or detector changes. Add hand-calculated bullish/bearish/directionless/flat fixtures, signed nonzero baselines, final-bar extrema, captured-basis mutation negatives, absent/invalid ATR, short/gapped windows, actual SQL observation roundtrip and real queued evaluations on SQLite and isolated PostgreSQL. Results UI and statistics remain later stories.
