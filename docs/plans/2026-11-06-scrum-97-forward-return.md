# SCRUM-97: versioned forward returns

Implement the approved first production outcome through the existing bounded outcome framework. Raw points equal the last required future M1 close minus the captured analytical detection-close price. Optional percent output is a separate definition with units `ratio`, matching the specified division by reference price (0.05 represents 5%, without multiplying stored values by 100). Percentage division uses fixed Decimal precision 28/HALF_EVEN; point subtraction preserves exact decimal differences.

Both definitions support an explicit `directional` boolean, default false. Continuation v1 uses captured `detector.context.source_direction`; reversal v1 uses captured `candidate_direction`, the opposite of its source move. Only an AVAILABLE detection-time context and registered direction contract may supply UP/+1 or DOWN/-1. Compression, unknown direction contracts and unavailable captured direction return NOT_APPLICABLE for directional output. No later component, occurrence or future price supplies the sign. Zero reference price makes ratio output NOT_APPLICABLE. Window/session insufficiency remains the framework's first gate.

Horizon is a positive canonical-M1 offset. Suggested defaults are 5/15/30/60, available as explicit selections rather than silently added to existing plans. The first future M1 candle starts at actual source close availability, so higher-timeframe detections cannot inspect earlier OHLC. Full horizon coverage and same-source-trading-day policy remain owned by SCRUM-120; missing open minutes are not replaced or extended.

Allow multiple configurations of a definition in an evaluation-plan-v2 plan so the four horizons can be selected together. Exact duplicate selections are rejected, including duplicates that become equal after default resolution. Canonical ordering includes configuration; v1 retains its definition-identity uniqueness rule and existing payloads/hashes remain unchanged. Framework execution must select an exact configuration rather than silently use the first definition match. Individual observations retain their own configuration identity and fixed units.

Register the definitions and algorithms and expose a read-only catalog for later UI selection. Production autonomous execution evaluates registered selections only after detector events, immutable X capture and primary population membership are persisted. Keep the analytical lease through bounded outcome batches, enforce owner checks at commit, support cancellation/partial output, and report COMPLETED only after required observations exist. Unregistered injected fixture algorithms remain explicitly pending; production submission rejects unavailable definitions. Queue submission may now accept supported forward returns; other unimplemented formulas remain unavailable.

Verify exact positive/negative/zero returns and all default horizons, inclusive last bar/detection-bar exclusion, captured sign (especially reversal), later-state independence, percentage/zero-reference behavior, calendar break/day/gap and higher-timeframe windows, multi-configuration hashes, persisted lineage/idempotency, actual queued worker output and incomplete/failed/cancelled status. Formula tests use hand-calculated values; orchestration tests use real source events and SQL context. Runs/results UI and other outcome families remain separate stories.
