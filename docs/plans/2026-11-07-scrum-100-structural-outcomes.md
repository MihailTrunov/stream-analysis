# SCRUM-100: canonical structural outcomes

Add categorical and EVENT_REFERENCE v1 definitions for the next confirmed swing, first confirmed structure break and next canonical TrendLeg transition. Categories expose HIGH/LOW, UP/DOWN, or canonical transition plus UP/DOWN. A complete window without a matching event is AVAILABLE/NO_EVENT categorically; its reference counterpart is NOT_APPLICABLE/NO_EVENT because the typed reference contract cannot encode a nonexistent event. Incomplete windows stay INSUFFICIENT_DATA. Parameters pin horizon, an optional source component instance (ANY by default), and an optional exact canonical TrendLeg transition. Missing required configured components produce NOT_APPLICABLE, not a fabricated NO_EVENT.

The inventory producer advances the same MarketStateAggregator and CandleAggregator used by DetectorRuntime, from the same immutable initialization origin, source revision, calendar and per-stream configuration. It consumes each component's emitted frozen canonical evidence objects and semantic reference function, without alternate centered swing logic or snapshot reconstruction. This downstream-only pass may consume future source bars in the declared same-trading-day envelope after detector processing has finished. It never invokes detectors or writes future DetectorEvents/X/population membership. Stop on the first missing open minute; any affected full-window evaluation remains insufficient. Check cancellation during source advancement; existing owned heartbeats remain active. Numeric-only plans skip this pass.

Retain selected canonical event type, component instance, category and frozen evidence JSON inside an optional reference payload. Omit this field entirely for legacy references so their JSON/content hashes remain unchanged. Store actual event_time, candle-labelled detection_time, close available_at, ordinal and semantic digest, preserving the distinction between original extreme time and when confirmation became knowable. Semantic event/result identity excludes database UUIDs through the existing semantic-reference function; debug evidence can retain attributed run IDs.

Preserve SCRUM-120's established observable order `(available_at, market-before-detector phase, within-phase ordinal)`. The three structural families consume market events: all market events at a source candle close precede that close's DetectorEvents, so they cannot become future outcomes merely because their phase-local ordinal is larger. Same-close later detector references remain eligible under the generic framework, while earlier/equal detector ordinals are rejected; optional detector-reference outcomes are outside this ticket. This clarifies the ticket's simplified same-bar wording using the actual canonical pipeline, rather than inventing a later market event. Cross-timeframe events remain excluded. Elapsed interpretation uses the retained source/downstream detection_time values; availability governs causality.

Use the registered bounded outcome worker, typed immutable observations and complete lineage. Restrict per-observation inventory input to the source trading-day envelope via binary search before the framework applies exact horizon/order filtering. Verify actual emitted swing/break/leg identities, categories and configuration filtering; no-event versus missing component; insufficient/gapped windows; phase/ordinal boundaries; legacy reference serialization; immutable evidence; UUID-independent semantic identity; and actual queued SQLite/PostgreSQL execution with unchanged source events when outcomes are added. No UI changes, alternative structural algorithms, event mutation or provider access.
