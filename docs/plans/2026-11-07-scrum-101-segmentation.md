# SCRUM-101: detection-time instrument/session partitions

Register three immutable versioned SegmentDefinitions: BY_INSTRUMENT, BY_SESSION and BY_INSTRUMENT_SESSION. Fields are a closed approved set (instrument_id and captured session_name), with distinct observed captured values as allowed buckets, explicit unavailable values and NON_OVERLAPPING policy. Each eligible source event belongs once to each selected definition's partition. Separate definitions may describe the same population independently; counts are never summed across definitions. Unsupported overlapping rules, arbitrary fields and segment parameters are rejected rather than silently interpreted. Future approved dimensions can extend segmentation without changing DetectorEvent semantics.

Use only the persisted DetectorEvent instrument and DetectionTimeContextSnapshot component session state. Never inspect OutcomeObservation values, future state, browser timezone or current calendar calculations to choose a bucket. Preserve the captured session name exactly: current OANDA calendars primarily label their provider session; this story does not invent regional sessions. Missing session state is an explicit unavailable bucket, not a dropped event or fabricated session. Form groups only from actual members, so empty allowed buckets never appear as samples.

Freeze each selected definition descriptor/fingerprint alongside the copied per-stream evaluation plan in the existing immutable JSON input manifest. Omit the new optional descriptor field for empty selections, preserving legacy manifest bytes and identities. Register segment parameter specs in preflight, source RunSnapshot creation and outcome plan-hash validation. Preserve DetectionConfigHash, source DetectorEvent truth and primary EventSet identity when only downstream grouping choices change. Validate pinned/current segment contracts before execution; reject unknown or changed contracts without generating results.

Membership is a deterministic read projection over immutable EventSet/X records, not a second mutable analytical truth. No schema migration or new membership table is required. Stream eligible rows in bounded pages and expose a reusable membership iterator for SCRUM-102. Return read-only group sizes and definition/bucket/source-lineage metadata from GET /evaluation-runs/{id}/segments, retaining partial-run status and selected-stream scope. No outcome statistics or profitability interpretations are added; aggregates and their persisted segment references remain SCRUM-102. A read-only /segment-definitions catalog supports explicit future UI selection.

Verify hand-calculated instrument/session/combined partitions, captured session boundaries and unavailable values, no empty groups, non-overlap and unsupported rule rejection, no future/outcome/timezone influence, frozen descriptor/hash roundtrips and backward compatibility, invalid preflight without writes, group sizes reconciling to eligible selected-stream events, run/plan lineage, real queued outcomes with segments on SQLite/PostgreSQL and unchanged source events across downstream plan changes. API tests use scratch databases only. Final Python/PostgreSQL regression also covers the separate threshold opening-order correction.
