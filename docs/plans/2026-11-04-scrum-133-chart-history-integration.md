# SCRUM-133 — shared history in chart navigation

Connect navigation to existing indexed source windows and durable range acquisition. A history tab's Move to first focuses a loaded candle, then reads another bounded window of the selected immutable revision. Only provider sources may extend beyond their retained revision; synthetic demo prices remain confined to their explicit source. Replay Move to remains a viewport-only operation over revealed candles.

Use a server navigation planner for provider acquisition and replay preparation. Pin the selected source's feed against configured account context, derive chart context and per-stream initialization from calendar buckets and the existing warm-up policy, split missing history intent into at most 32 requests of at most 31 days, and reject unverified dates or excessive periods. The UI polls focused-tab coverage, exposes pending/unavailable/failed/gap/conflict states, publishes reviewed complete coverage into an immutable input, and adopts that source without changing detector settings.

Persist pending request identities with the tab so restoration resumes only when focused. Cancelling navigation stops that tab's adoption/polling; shared durable retention remains independent. Generation and abort guards prevent obsolete responses, timeframe changes or other tabs from changing the current chart. Replay entry fixes the endpoint and remains paused; no acquisition is triggered by Move to during an active replay.

Leftward navigation loads another bounded window when the user pans to its edge, preserving an overlapping viewport anchor instead of accumulating all prices in DOM memory. A manual earlier-history action provides keyboard access and retry at a real limit. Show actual provider/calendar limits and errors rather than synthetic candles. Existing zoom/timeframe/pattern controls stay independent.

Verify local unloaded navigation, provider preparation/poll/publication, initialization-aware replay entry, cancellation and restored focus, pending/terminal states, stale responses, cross-tab isolation, higher-timeframe selection, and replay cursor/future-data isolation in unit/API/browser tests. Live-provider acceptance remains separate from fake-ingress checks.

## Delivered behavior

- Move to focuses the containing candle, including a selected minute inside a higher-timeframe candle. An unloaded point inside the retained revision loads another immutable window; it does not require a provider account or create an analytical run.
- Left-edge panning and the keyboard-accessible Load earlier candles action replace the bounded window with older data and overlapping context. Programmatic focus does not trigger acquisition. Synthetic sources stop explicitly at their own beginning.
- Provider navigation uses `POST /history/navigation`. The server verifies source/feed identity, instrument/calendar/configuration support and minute-aligned verified dates, then derives display context and analytical warm-up using existing calendar buckets and the existing initialization policy. It creates durable requests of at most 31 days each, capped at 32 requests. It does not call a provider itself.
- The focused tab polls coverage, publishes only fully available reviewed hashes through `/history/inputs`, loads prices from the resulting immutable input and adopts it as the tab source. Pending, failed, unavailable, gap and conflict states remain distinct. Retry navigation rechecks durable coverage; it does not silently create a fresh provider retry.
- Pending request IDs and the current history-window endpoint are saved with the tab. Hidden tabs stop polling, painting and automatic historical calculation; focusing a restored pending tab resumes its coverage check. Cancel navigation stops tab adoption/polling while shared durable acquisition remains independent. Source/timeframe changes invalidate obsolete responses.
- Provider Start replay from prepares source initialization first, creates a fresh ordinary analysis session and opens paused. A blank advanced end uses the latest completed instant inside verified calendar coverage at preparation; waiting for acquisition does not move that fixed endpoint. Editing the end pins an earlier choice. Runtime-selected dates override dataset defaults when recovering a server replay into a tab.

The browser retains its 500-candle windows and sixteen-window immutable request cache. This does not claim constant-time calendar planning or year-scale composition: source authentication, calendar scans and materialized publication retain the costs and bounds documented in the backend increments. No new schema migration is required; the existing shared-request migration `20261104_13` remains a prerequisite.
